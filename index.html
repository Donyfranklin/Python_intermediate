Object-Oriented Programming (OOP)

A programming paradigm that organises code around objects and classes instead of functions and logic.

🏛️
TOPIC 1.0

What is OOP?

Understanding the programming paradigm that powers modern Python applications.
📖 DEFINITION

Object-Oriented Programming (OOP) is a programming style (paradigm) where we organise code into objects that combine data (attributes) and behaviour (methods). Python is an object-oriented language — almost everything in Python is an object.

🏠
REAL-WORLD ANALOGY

Think of a House Blueprint. The blueprint (class) defines how a house should look — number of rooms, windows, doors. Each actual house built from that blueprint is an object. Multiple houses can be built from one blueprint, each with different colours or furniture.

Paradigm
A style or way of programming. OOP is one paradigm; others include Procedural and Functional.
Class
A blueprint/template for creating objects. Defines structure and behaviour.
Object
A real, usable instance created from a class. Has its own data.
Instance
Another word for object. "Creating an instance" = making an object from a class.
Attribute
A variable that belongs to a class or object (stores data).
Method
A function defined inside a class (defines behaviour).

The 4 Pillars of OOP are: Encapsulation, Inheritance, Polymorphism, Abstraction. We will study each in detail.

Simple OOP vs Procedural comparison
Python — OOP vs Procedural
# ── PROCEDURAL style (old way) ──
def dog_bark(name):
    return f"{name} says Woof!"

print(dog_bark("Bruno"))

# ── OOP style (modern way) ──
class Dog:
    def __init__(self, name):   # constructor
        self.name = name        # attribute

    def bark(self):              # method
        return f"{self.name} says Woof!"

d = Dog("Bruno")   # create object
print(d.bark())
▶ OUTPUT
Bruno says Woof! Bruno says Woof!

TOPIC 1.1

Classes & Objects

The core building blocks of OOP — creating blueprints and real instances from them.
📖 DEFINITION — CLASS

A class is a user-defined data type (blueprint) that bundles data (attributes) and functions (methods) together. Classes are created using the class keyword.

📖 DEFINITION — OBJECT

An object is a specific instance of a class. You create (instantiate) an object by calling the class like a function: obj = ClassName(). Each object has its own copy of the class attributes.

🚗
REAL-WORLD ANALOGY

Car is a class. Your Maruti Swift and neighbour's Honda City are objects. Both have the same structure (engine, wheels, seats) but different data (colour, model, year).

class keyword
Used to define a class in Python.
instantiation
The process of creating an object from a class.
class attribute
Shared by ALL objects of the class.
instance attribute
Unique to each individual object.
dot notation
obj.attribute or obj.method() — how you access class members.
pass
Placeholder to create an empty class body without error.
Example 1 — Basic class and object creation
Python
# Define a class using 'class' keyword
class Student:
    # Class attribute (shared by all students)
    school = "Python High School"

    # Constructor method
    def __init__(self, name, grade):
        # Instance attributes (unique to each object)
        self.name  = name
        self.grade = grade

    # Instance method
    def introduce(self):
        return f"Hi! I am {self.name}, Grade {self.grade} at {self.school}."

    def is_pass(self, score):
        return "Pass ✅" if score >= 40 else "Fail ❌"

# Creating objects (instances) from the class
s1 = Student("Arun", 10)     # instantiation
s2 = Student("Priya", 11)

# Access attributes using dot notation
print(s1.name)               # instance attribute
print(Student.school)        # class attribute

# Call methods
print(s1.introduce())
print(s2.introduce())
print("Result:", s1.is_pass(78))
print("Result:", s2.is_pass(35))
▶ OUTPUT
Arun Python High School Hi! I am Arun, Grade 10 at Python High School. Hi! I am Priya, Grade 11 at Python High School. Result: Pass ✅ Result: Fail ❌
💡

Key point: s1 and s2 share the same class attribute school, but each has their own instance attributes name and grade. Changing s1.name does NOT affect s2.name.

TOPIC 1.2

The __init__ Method (Constructor)

The special method that runs automatically when an object is created.
📖 DEFINITION

The __init__ method is called a constructor. It is automatically called whenever a new object is created from the class. Its job is to initialise (set up) the object's attributes with starting values. The double underscores (dunders) before and after are Python's way of marking special built-in methods.

Constructor
A special method called when an object is first created. In Python, this is __init__.
__init__
Short for "initialise". Sets up object data when created.
dunder / magic method
Methods with double underscores on both sides. Python calls them automatically.
initialise
To give an object its starting values when it is first created.
Example — __init__ with default values
Python
class Car:
    def __init__(self, brand, model, year=2024):
        """
        self  → the new object being created
        brand → passed by the user
        year  → has a default value of 2024
        """
        self.brand = brand
        self.model = model
        self.year  = year
        self.speed = 0         # default speed at creation

    def details(self):
        return f"{self.year} {self.brand} {self.model}"

    def accelerate(self, amount):
        self.speed += amount
        return f"Speed: {self.speed} km/h"

# year is not given → uses default 2024
c1 = Car("Toyota", "Camry")
c2 = Car("Honda", "City", 2022)

print(c1.details())
print(c2.details())
print(c1.accelerate(60))
print(c1.accelerate(20))
▶ OUTPUT
2024 Toyota Camry 2022 Honda City Speed: 60 km/h Speed: 80 km/h

TOPIC 1.3

The self Parameter

How Python links a method call to the correct object.
📖 DEFINITION

self is a reference to the current instance (object) of the class. It is the first parameter in every instance method and is automatically passed by Python when you call obj.method(). You can technically name it anything, but self is the universal Python convention.

🪞
REAL-WORLD ANALOGY

Think of self as the word "I" or "my" in a sentence. When Arun says "my name is Arun", the word my refers to Arun. When Priya says "my name is Priya", my refers to Priya. self works the same way — it refers to whichever object is currently being used.

Python — self explained
class Person:
    def __init__(self, name, age):
        self.name = name   # 'self' refers to the new object
        self.age  = age

    def greet(self):        # 'self' = whichever object calls this
        print(f"I am {self.name}, aged {self.age}.")

p1 = Person("Arun", 20)
p2 = Person("Priya", 22)

# Python internally converts this:
p1.greet()
# → Person.greet(p1)  ← self = p1

p2.greet()
# → Person.greet(p2)  ← self = p2
▶ OUTPUT
I am Arun, aged 20. I am Priya, aged 22.
📌

Remember: self is NOT a keyword in Python — it's just a convention. You could name it this or me, but always use self so others can read your code easily.

TOPIC 1.4

Attributes & Methods in Detail

Understanding the two types of attributes and three types of methods.
📖 ATTRIBUTES

Attributes are variables that store data inside a class or object. There are two kinds: Class attributes (shared by all objects) and Instance attributes (different for each object).

Class Attribute
Defined directly in the class body. Shared by all instances. Access via ClassName.attr
Instance Attribute
Defined inside __init__ using self.attr. Each object has its own copy.
Instance Method
Takes self as first param. Works with instance data. Most common type.
Class Method
Takes cls as first param. Decorated with @classmethod. Works with class data.
Static Method
No self or cls. Decorated with @staticmethod. Pure utility function.
getter / setter
Methods used to read (get) or update (set) private attributes safely.
Python — Attributes & Methods
class Circle:
    pi = 3.14159          # CLASS attribute — shared by all circles

    def __init__(self, radius):
        self.radius = radius  # INSTANCE attribute — unique per object

    # Instance method — uses self
    def area(self):
        return Circle.pi * self.radius ** 2

    def circumference(self):
        return 2 * Circle.pi * self.radius

    # Class method — uses cls
    @classmethod
    def change_pi(cls, new_pi):
        cls.pi = new_pi

    # Static method — no self/cls needed
    @staticmethod
    def is_valid_radius(r):
        return r > 0

c1 = Circle(5)
c2 = Circle(3)

print(f"Area of c1: {c1.area():.2f}")
print(f"Circumference of c2: {c2.circumference():.2f}")
print("Valid radius -5?", Circle.is_valid_radius(-5))
▶ OUTPUT
Area of c1: 78.54 Circumference of c2: 18.85 Valid radius -5? False

TOPIC 1.5

Inheritance

Reusing code by building new classes on top of existing ones.
📖 DEFINITION

Inheritance is the process where one class (called the child class or subclass) acquires the properties (attributes) and behaviours (methods) of another class (called the parent class, superclass, or base class). This promotes code reuse — you don't have to re-write the same code again.

👨‍👩‍👧
REAL-WORLD ANALOGY

Children inherit features from their parents — eye colour, height, surname. They also have their own unique features. Similarly, a child class inherits from a parent class and can also add its own new methods.

parent class / base class / superclass
The class being inherited FROM. Already has the shared code.
child class / derived class / subclass
The class that INHERITS from the parent. Gets all parent features + adds its own.
super()
Built-in function to call a method from the parent class.
method overriding
Child class redefines a method from the parent with new behaviour.
isinstance()
Checks if an object is an instance of a class (or its parent).
issubclass()
Checks if one class is a subclass of another.
Example 1 — Basic Inheritance
Python — Single Inheritance
# PARENT CLASS (Base class)
class Animal:
    def __init__(self, name, sound):
        self.name  = name
        self.sound = sound

    def speak(self):
        return f"{self.name} says {self.sound}!"

    def eat(self):
        return f"{self.name} is eating."

# CHILD CLASS (inherits from Animal)
class Dog(Animal):            # Dog IS-A Animal
    def __init__(self, name, breed):
        super().__init__(name, "Woof")  # call parent __init__
        self.breed = breed          # new attribute in child

    def fetch(self):                # new method in child
        return f"{self.name} fetches the ball! 🎾"

class Cat(Animal):
    def __init__(self, name):
        super().__init__(name, "Meow")

    def purr(self):
        return f"{self.name} purrs 😻"

dog = Dog("Bruno", "Labrador")
cat = Cat("Whiskers")

print(dog.speak())    # inherited from Animal
print(dog.eat())      # inherited from Animal
print(dog.fetch())    # Dog's own method
print(cat.speak())
print(cat.purr())

print(isinstance(dog, Animal))   # True
print(issubclass(Dog, Animal))   # True
▶ OUTPUT
Bruno says Woof! Bruno is eating. Bruno fetches the ball! 🎾 Whiskers says Meow! Whiskers purrs 😻 True True

TOPIC 1.6

Types of Inheritance

Python supports 5 types of inheritance — each solves different design problems.
TypeDescriptionStructure
SingleOne child inherits from one parentA → B
MultipleOne child inherits from more than one parentA, B → C
MultilevelChained inheritance across multiple levelsA → B → C
HierarchicalMultiple children inherit from one parentA → B, A → C
HybridCombination of two or more typesMixed of above
Multilevel Inheritance
Python — Multilevel Inheritance
class LivingBeing:
    def breathe(self):
        return "Breathing..."

class Animal(LivingBeing):     # Animal ← LivingBeing
    def move(self):
        return "Moving..."

class Dog(Animal):             # Dog ← Animal ← LivingBeing
    def bark(self):
        return "Woof!"

d = Dog()
print(d.breathe())  # from LivingBeing (grandparent)
print(d.move())     # from Animal (parent)
print(d.bark())     # Dog's own
▶ OUTPUT
Breathing... Moving... Woof!
Multiple Inheritance
Python — Multiple Inheritance
class Mother:
    def cooking(self):
        return "Cooking skill from Mother 🍳"

class Father:
    def driving(self):
        return "Driving skill from Father 🚗"

class Child(Mother, Father):  # inherits BOTH
    def studying(self):
        return "Child's own skill: Studying 📚"

c = Child()
print(c.cooking())
print(c.driving())
print(c.studying())

# MRO — Method Resolution Order
print(Child.__mro__)
▶ OUTPUT
Cooking skill from Mother 🍳 Driving skill from Father 🚗 Child's own skill: Studying 📚 (<class 'Child'>, <class 'Mother'>, <class 'Father'>, <class 'object'>)
💡

MRO (Method Resolution Order) is the order Python uses to search for a method when you call it. It follows the C3 linearisation algorithm, going from most specific (child) to least specific (object). When two parent classes have the same method, Python picks from the one listed first.

TOPIC 1.7

Polymorphism

One interface, many forms — the same method name behaves differently in different classes.
📖 DEFINITION

Polymorphism (from Greek: poly = many, morph = forms) means that the same method name can behave differently depending on the class it belongs to. It allows you to write a single line of code that works with many types of objects.

🔊
REAL-WORLD ANALOGY

The "+", operator in Python is polymorphic: 2 + 3 = 5 (addition) but "Hello" + " World" = "Hello World" (concatenation). Same symbol, different behaviour based on the type.

Method Overriding
Child class redefines a parent method. Called at runtime (run-time polymorphism).
Duck Typing
"If it walks like a duck, it's a duck." Python cares about behaviour, not type.
Operator Overloading
Redefine how operators (+, -, ==) work for custom classes using dunder methods.
len() polymorphism
len() works on strings, lists, tuples, dicts — each returns a count differently.
Example 1 — Method Overriding (Runtime Polymorphism)
Python
class Shape:
    def draw(self):
        print("Drawing a generic shape")

    def area(self):
        return 0

class Circle(Shape):
    def __init__(self, r): self.r = r
    def draw(self):   # OVERRIDES parent
        print(f"Drawing Circle with radius {self.r} ⭕")
    def area(self): return 3.14 * self.r ** 2

class Rectangle(Shape):
    def __init__(self, w, h): self.w = w; self.h = h
    def draw(self):
        print(f"Drawing Rectangle {self.w}x{self.h} ▭")
    def area(self): return self.w * self.h

class Triangle(Shape):
    def __init__(self, b, h): self.b = b; self.h = h
    def draw(self):
        print(f"Drawing Triangle base {self.b} height {self.h} △")
    def area(self): return 0.5 * self.b * self.h

# Polymorphism in action
shapes = [Circle(5), Rectangle(4, 6), Triangle(3, 8)]

for s in shapes:
    s.draw()                        # same call, different output
    print(f"  Area = {s.area()}")
▶ OUTPUT
Drawing Circle with radius 5 ⭕ Area = 78.5 Drawing Rectangle 4x6 ▭ Area = 24 Drawing Triangle base 3 height 8 △ Area = 12.0
Example 2 — Operator Overloading using dunder methods
Python
class Fraction:
    def __init__(self, num, den):
        self.num = num
        self.den = den

    def __str__(self):            # makes print() readable
        return f"{self.num}/{self.den}"

    def __add__(self, other):     # overloads +
        n = self.num * other.den + other.num * self.den
        d = self.den * other.den
        return Fraction(n, d)

    def __mul__(self, other):     # overloads *
        return Fraction(self.num * other.num, self.den * other.den)

    def __eq__(self, other):      # overloads ==
        return self.num * other.den == other.num * self.den

f1 = Fraction(1, 2)
f2 = Fraction(1, 3)
print("f1 + f2 =", f1 + f2)
print("f1 * f2 =", f1 * f2)
print("f1 == f2?", f1 == f2)
▶ OUTPUT
f1 + f2 = 5/6 f1 * f2 = 1/6 f1 == f2? False

TOPIC 1.8

Encapsulation

Protecting data by restricting direct access from outside the class.
📖 DEFINITION

Encapsulation means bundling data (attributes) and methods together in a class, and controlling access to the data. It prevents outsiders from directly modifying important data, maintaining data integrity. This is achieved using access modifiers.

💊
REAL-WORLD ANALOGY

A medicine capsule — the active ingredients are hidden inside. You can take the medicine (use the object) without needing to see or change the chemical formula inside (private data). The capsule's outer shell controls access.

name
Public
Accessible from anywhere — inside class, outside class, and in child classes.
_name
Protected
Single underscore. Convention — "don't use outside class." Not enforced by Python.
__name
Private
Double underscore. Name-mangled by Python (_ClassName__name). Harder to access outside.
access modifier
Controls who can access class attributes. Public, Protected, Private.
name mangling
Python renames __attr to _ClassName__attr to make it hard to access outside.
@property
A decorator that makes a method behave like an attribute (getter).
setter
A method to update a private attribute with validation.
data integrity
Keeping data accurate and valid. Encapsulation helps enforce this.
decorator
A function (like @property) that modifies or wraps another function's behaviour.
Example — Bank Account with private data
Python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner     = owner         # public
        self._bank     = "PyBank"     # protected (by convention)
        self.__balance = balance       # private (name-mangled)
        self.__pin     = 1234          # private

    # Getter — read-only access to balance
    @property
    def balance(self):
        return self.__balance

    # Setter — controlled update
    @balance.setter
    def balance(self, amount):
        if amount < 0:
            print("❌ Balance cannot be negative!")
        else:
            self.__balance = amount

    def deposit(self, amount, pin):
        if pin != self.__pin:
            return "❌ Wrong PIN!"
        self.__balance += amount
        return f"✅ Deposited ₹{amount}. Balance: ₹{self.__balance}"

    def withdraw(self, amount, pin):
        if pin != self.__pin:
            return "❌ Wrong PIN!"
        if amount > self.__balance:
            return "❌ Insufficient balance!"
        self.__balance -= amount
        return f"✅ Withdrawn ₹{amount}. Remaining: ₹{self.__balance}"

acc = BankAccount("Priya", 10000)
print("Balance:", acc.balance)          # uses @property getter
print(acc.deposit(5000, 1234))
print(acc.withdraw(2000, 9999))         # wrong pin
print(acc.withdraw(2000, 1234))

# acc.__balance → AttributeError (private!)
# But name-mangled version still accessible:
print(acc._BankAccount__balance)         # 13000
▶ OUTPUT
Balance: 10000 ✅ Deposited ₹5000. Balance: ₹15000 ❌ Wrong PIN! ✅ Withdrawn ₹2000. Remaining: ₹13000 13000

TOPIC 1.9

Abstraction

Hiding internal complexity and showing only what's necessary.
📖 DEFINITION

Abstraction means hiding complex implementation details and exposing only the essential features to the user. In Python, abstraction is achieved using Abstract Base Classes (ABC). An abstract class is a class that cannot be instantiated — it only serves as a contract that child classes must follow.

📱
REAL-WORLD ANALOGY

When you press the camera button on your phone, you get a photo — you don't need to understand sensors, apertures, or processing algorithms. The phone abstracts the complexity and gives you a simple interface: just press the button.

ABC (Abstract Base Class)
A class from the abc module that provides the framework for defining abstract classes.
@abstractmethod
A decorator that marks a method as abstract — any child class MUST implement it.
abstract class
Cannot be instantiated. Acts as a template that enforces a contract on child classes.
concrete method
A method in an abstract class that HAS an implementation (not abstract).
instantiate
Create an object from a class. You CANNOT instantiate an abstract class.
contract / interface
A guarantee that child classes implement certain methods. ABC enforces this.
Python — Abstraction with ABC
from abc import ABC, abstractmethod

# Abstract class — cannot create objects of this class
class Payment(ABC):
    def __init__(self, amount):
        self.amount = amount

    @abstractmethod
    def pay(self):
        pass                  # child MUST implement this

    @abstractmethod
    def verify(self):
        pass                  # child MUST implement this

    # Concrete method — available to all children
    def receipt(self):
        return f"Payment of ₹{self.amount} processed."

# Concrete class — implements abstract methods
class UPIPayment(Payment):
    def pay(self):
        return f"Paid ₹{self.amount} via UPI 📱"
    def verify(self):
        return "UPI PIN verified ✅"

class CardPayment(Payment):
    def pay(self):
        return f"Paid ₹{self.amount} via Card 💳"
    def verify(self):
        return "OTP verified ✅"

# p = Payment(100)  → TypeError! Cannot instantiate abstract class

u = UPIPayment(500)
c = CardPayment(1200)

for payment in [u, c]:
    print(payment.verify())
    print(payment.pay())
    print(payment.receipt())
    print("---")
▶ OUTPUT
UPI PIN verified ✅ Paid ₹500 via UPI 📱 Payment of ₹500 processed. --- OTP verified ✅ Paid ₹1200 via Card 💳 Payment of ₹1200 processed. ---

TOPIC 1.10

Special / Dunder / Magic Methods

Built-in methods Python calls automatically to make your objects work like native types.
📖 DEFINITION

Dunder methods (short for "double underscore methods") are special methods in Python with double underscores on both sides (e.g., __str__, __len__). Python calls them automatically in response to built-in operations (like print(), len(), +, ==). They let your objects behave like built-in Python types.

Dunder MethodTriggered byPurpose
__init__(self)ClassName()Constructor — initialise object
__str__(self)print(obj), str(obj)Human-readable string
__repr__(self)repr(obj)Developer-readable string
__len__(self)len(obj)Return length of object
__add__(self, other)obj1 + obj2Addition operator
__sub__(self, other)obj1 - obj2Subtraction operator
__eq__(self, other)obj1 == obj2Equality comparison
__lt__(self, other)obj1 < obj2Less-than comparison
__getitem__(self,key)obj[key]Indexing operator
__del__(self)del objDestructor — cleanup on delete
Python — Special Methods
class ShoppingCart:
    def __init__(self):
        self.items = []

    def add(self, item, price):
        self.items.append({"item": item, "price": price})

    def __len__(self):               # len(cart)
        return len(self.items)

    def __str__(self):               # print(cart)
        lines = [f"  - {i['item']}: ₹{i['price']}" for i in self.items]
        return "🛒 Cart:\n" + "\n".join(lines)

    def __add__(self, other):        # cart1 + cart2
        merged = ShoppingCart()
        merged.items = self.items + other.items
        return merged

    def __getitem__(self, index):   # cart[0]
        return self.items[index]

    def total(self):
        return sum(i["price"] for i in self.items)

cart1 = ShoppingCart()
cart1.add("Rice 5kg", 250)
cart1.add("Dal 1kg", 120)

cart2 = ShoppingCart()
cart2.add("Milk 1L", 60)

print(cart1)                        # __str__
print("Items:", len(cart1))         # __len__
print("First item:", cart1[0])      # __getitem__
print("Total: ₹", cart1.total())

combined = cart1 + cart2           # __add__
print("\nCombined Cart Total: ₹", combined.total())
▶ OUTPUT
🛒 Cart: - Rice 5kg: ₹250 - Dal 1kg: ₹120 Items: 2 First item: {'item': 'Rice 5kg', 'price': 250} Total: ₹ 370 Combined Cart Total: ₹ 430

TOPIC 1.11

Class Methods & Static Methods

Distinguish between methods that need instance data, class data, or no data at all.
TypeDecoratorFirst ParamCan AccessUse Case
Instance Method(none)selfInstance + Class dataMost methods — work on object data
Class Method@classmethodclsClass data onlyFactory methods, alternate constructors
Static Method@staticmethod(none)Nothing automaticallyUtility functions related to the class
@classmethod
Decorator that converts a method to a class method. Receives cls (the class) instead of self.
@staticmethod
Decorator that creates a method with no automatic arguments. Pure utility function.
cls
Refers to the class itself (not an instance). Like self but for the class.
factory method
A class method used as an alternate way to create objects (alternate constructor).
Python
class Temperature:
    unit = "Celsius"        # class attribute

    def __init__(self, celsius):
        self.celsius = celsius   # instance attribute

    # Instance method — uses self
    def to_fahrenheit(self):
        return (self.celsius * 9/5) + 32

    # Class method — factory: create from Fahrenheit
    @classmethod
    def from_fahrenheit(cls, fahrenheit):
        celsius = (fahrenheit - 32) * 5/9
        return cls(celsius)           # creates Temperature object

    # Class method — change class attribute
    @classmethod
    def set_unit(cls, unit):
        cls.unit = unit

    # Static method — utility, no self/cls
    @staticmethod
    def is_freezing(celsius):
        return celsius <= 0

# Create from Celsius
t1 = Temperature(100)
print(f"{t1.celsius}°C = {t1.to_fahrenheit()}°F")

# Create from Fahrenheit (factory)
t2 = Temperature.from_fahrenheit(98.6)
print(f"Body temp: {t2.celsius:.2f}°C")

# Static method
print("Is -5 freezing?", Temperature.is_freezing(-5))
▶ OUTPUT
100°C = 212.0°F Body temp: 37.00°C Is -5 freezing? True

TOPIC 1.12

Composition (HAS-A Relationship)

Building complex objects by including simpler objects inside them.
📖 DEFINITION

Composition is a design principle where a class contains objects of other classes as attributes. This models a "HAS-A" relationship (a Car HAS-A Engine). Composition is often preferred over deep inheritance chains — it keeps code flexible and modular.

Inheritance → IS-A relationship (Dog IS-A Animal) Composition → HAS-A relationship (Car HAS-A Engine) class Engine: ← standalone class class Wheel: ← standalone class class Car: self.engine = Engine() ← Car HAS-A Engine self.wheels = [Wheel() for _ in range(4)]
Python — Composition
class Battery:
    def __init__(self, capacity_kwh):
        self.capacity = capacity_kwh
        self.charge   = 100   # percentage

    def status(self):
        return f"Battery {self.capacity}kWh — {self.charge}% charged"

class Motor:
    def __init__(self, horsepower):
        self.hp = horsepower

    def start(self):
        return f"⚡ Electric motor ({self.hp}hp) started silently!"

class GPS:
    def navigate(self, destination):
        return f"🗺️ Navigating to {destination}..."

# ElectricCar HAS-A Battery, HAS-A Motor, HAS-A GPS
class ElectricCar:
    def __init__(self, brand):
        self.brand   = brand
        self.battery = Battery(82)   # composition
        self.motor   = Motor(670)    # composition
        self.gps     = GPS()          # composition

    def start_trip(self, destination):
        print(f"=== {self.brand} Trip ===")
        print(self.battery.status())
        print(self.motor.start())
        print(self.gps.navigate(destination))

tesla = ElectricCar("Tesla Model S")
tesla.start_trip("Chennai Central")
▶ OUTPUT
=== Tesla Model S Trip === Battery 82kWh — 100% charged ⚡ Electric motor (670hp) started silently! 🗺️ Navigating to Chennai Central...

TOPIC 1.13

Inner Classes (Nested Classes)

Defining a class inside another class to group related functionality tightly.
📖 DEFINITION

An inner class (also called a nested class) is a class defined inside the body of another class. It is used when one class is closely related to another and doesn't make sense to exist independently. The outer class can create instances of the inner class.

Python — Inner Class
class School:
    def __init__(self, name):
        self.name     = name
        self.students = []

    # Inner class — only meaningful inside School
    class Student:
        def __init__(self, name, roll):
            self.name = name
            self.roll = roll

        def info(self):
            return f"Roll {self.roll}: {self.name}"

    def admit(self, name, roll):
        # Outer class creates inner class object
        s = School.Student(name, roll)
        self.students.append(s)

    def roster(self):
        print(f"=== {self.name} Student Roster ===")
        for s in self.students:
            print("  ", s.info())

sc = School("Python Academy")
sc.admit("Arun", 101)
sc.admit("Priya", 102)
sc.admit("Karthik", 103)
sc.roster()
▶ OUTPUT
=== Python Academy Student Roster === Roll 101: Arun Roll 102: Priya Roll 103: Karthik

Understanding what each mode does when you open a file.
📖 DEFINITION

The mode parameter in open() tells Python how to open the file — whether to read it, write to it, create it, etc. Using the wrong mode can destroy your data, so always choose carefully.

ModeNameFile must exist?Creates file?Behaviour

'w'WriteNoYes⚠️ Overwrites entire file! Creates if not exists.
'a'AppendNoYesAdds to end of file. Creates if not exists.
'x'Exclusive CreateMust NOT existYesCreates new file. Error if file already exists.

Warning: Opening with 'w' mode deletes all existing content in the file immediately, even before you write anything new. Use 'a' if you want to keep the existing content and add more.

TOPIC 2.4

Append Mode

Add new content at the end of an existing file without losing original data.
📖 DEFINITION

Opening a file in append mode ('a') moves the cursor to the end of the file before writing. All new content is added after existing content. This is perfect for log files where you keep adding new entries over time.

Python — Append Mode (Log File)
import datetime

def log_event(message):
    """Append a timestamped message to a log file."""
    timestamp = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    with open("app.log", "a", encoding="utf-8") as f:
        f.write(f"[{timestamp}] {message}\n")

# Simulate 3 events
log_event("App started")
log_event("User 'Arun' logged in")
log_event("Database connection established")

# Read back the log
with open("app.log") as f:
    print(f.read())

TOPIC 2.5

seek() and tell() — File Cursor

Navigate to any position in a file using the internal file cursor.
📖 DEFINITION

Every open file has an internal cursor (like a reading pointer) that tracks the current position in bytes. tell() returns the current position. seek(n) moves the cursor to byte position n. This lets you re-read or jump to specific parts of a file.

cursor / file pointer
Internal marker that tracks where the next read/write will happen in the file.
tell()
Returns the current cursor position as a byte offset from the start.
seek(n)
Moves cursor to byte position n. seek(0) goes back to the beginning.
byte offset
Position measured in bytes from the beginning of the file.
Python — seek() and tell()
# Create a sample file
with open("test.txt", "w") as f:
    f.write("Hello World!\nPython is fun!")

with open("test.txt", "r") as f:
    print("Position:", f.tell())     # 0 (start)

    first = f.read(5)               # read 5 chars
    print("Read 5 chars:", first)    # 'Hello'
    print("Position now:", f.tell())  # 5

    f.seek(0)                        # go back to start
    print("After seek(0):", f.tell())

    line1 = f.readline()
    print("Line 1:", line1.strip())

    print("Position after line1:", f.tell())

    f.seek(0)                        # rewind again
    full = f.read()
    print("Full file:\n", full)
▶ OUTPUT
Position: 0 Read 5 chars: Hello Position now: 5 After seek(0): 0 Line 1: Hello World! Position after line1: 13 Full file: Hello World! Python is fun!

TOPIC 2.6

The with Statement (Context Manager)

The safest way to open files — automatically handles closing even if an error occurs.
📖 DEFINITION

The with statement creates a context manager that ensures the file is automatically closed when the block ends — even if an exception (error) occurs inside. This prevents resource leaks (unclosed files consuming memory).

context manager
An object that manages resources — sets them up (open) and cleans up (close) automatically.
resource leak
When a program forgets to close files/connections, wasting system memory and limits.
with...as
Opens the file and assigns the file object to the variable after 'as'.
__enter__ / __exit__
Dunder methods that power context managers. with calls these automatically.
Python — with vs without
# ❌ WITHOUT 'with' — risky (what if error occurs before close?)
f = open("notes.txt", "r")
data = f.read()
# if error here, f.close() never runs!
f.close()

# ✅ WITH 'with' — safe, auto-closes always
with open("notes.txt", "r") as f:
    data = f.read()
# file is closed HERE automatically
print("File closed?", f.closed)   # True

# Open multiple files at once with 'with'
with open("input.txt", "r") as src, \
     open("output.txt", "w") as dst:
    for line in src:
        dst.write(line.upper())   # copy file in UPPERCASE
print("Copied in uppercase ✅")
▶ OUTPUT
File closed? True Copied in uppercase ✅

Exception Handling in File I/O

Gracefully handle errors using try-except-finally blocks.
📖 DEFINITION

File operations can fail — the file might not exist, you might not have permission to read it, or the disk might be full. Exception handling using try-except-finally lets your program handle these errors gracefully instead of crashing.

exception
An error that occurs during program execution, disrupting normal flow.
try
Block where risky code goes. Python "tries" to run it.
except
Runs if an exception occurs in the try block. Catches and handles the error.
finally
Always runs — whether exception occurred or not. Used for cleanup.
FileNotFoundError
Raised when open() cannot find the specified file.
PermissionError
Raised when you don't have rights to read/write the file.
IOError / OSError
General I/O error. OSError is the base class for file-related errors.
gracefully
Handling errors smoothly without crashing — showing a helpful message instead.
Python — Full Exception Handling
def read_file_safe(filename):
    """Read a file safely with full error handling."""
    f = None
    try:
        f = open(filename, "r", encoding="utf-8")
        content = f.read()
        print(f"✅ File read successfully!")
        return content

    except FileNotFoundError:
        print(f"❌ Error: '{filename}' not found.")
        return None

    except PermissionError:
        print(f"❌ Error: No permission to read '{filename}'.")
        return None

    except UnicodeDecodeError:
        print(f"❌ Error: Cannot decode '{filename}'. Try binary mode.")
        return None

    except OSError as e:
        print(f"❌ OS Error: {e}")
        return None

    finally:
        # always runs — clean up resources
        if f and not f.closed:
            f.close()
        print(f"[finally] Cleanup done for: {filename}")

# Test with valid and invalid files
data = read_file_safe("notes.txt")   # exists
print()
data = read_file_safe("ghost.txt")   # doesn't exist
▶ OUTPUT
✅ File read successfully! [finally] Cleanup done for: notes.txt ❌ Error: 'ghost.txt' not found. [finally] Cleanup done for: ghost.txt

📖 DEFINITION

Binary files store data as raw bytes, not readable text. Images (.jpg, .png), audio (.mp3), PDFs, and executable files (.exe) are all binary. Use mode 'rb' to read and 'wb' to write binary files.

bytes
The basic unit of data in binary files. Python's bytes type stores raw byte sequences.
b'...'
A bytes literal in Python. E.g., b'Hello' is the bytes version of the string 'Hello'.
'rb' mode
Read Binary — opens file for reading raw bytes.
'wb' mode
Write Binary — opens file for writing raw bytes.
encode()
Convert string to bytes. e.g., "hello".encode("utf-8")
decode()
Convert bytes back to string. e.g., b"hello".decode("utf-8")
Python — Binary Files
# Write binary data
data = bytes([80, 121, 116, 104, 111, 110])  # "Python" in ASCII

with open("data.bin", "wb") as f:
    f.write(data)
print("Binary file written ✅")

# Read binary data
with open("data.bin", "rb") as f:
    raw = f.read()
    print("Raw bytes :", raw)
    print("As string :", raw.decode("utf-8"))
    print("As int list:", list(raw))

# Practical: Binary file copy (works for ANY file type)
def copy_file(source, destination):
    with open(source, "rb") as src:
        with open(destination, "wb") as dst:
            while True:
                chunk = src.read(4096)   # read 4KB at a time
                if not chunk:
                    break
                dst.write(chunk)
    print(f"Copied: {source} → {destination}")

copy_file("data.bin", "data_backup.bin")

CSV File Handling

Reading and writing comma-separated values — the most common data exchange format.
📖 DEFINITION

A CSV (Comma-Separated Values) file stores tabular data as plain text where each row is a line and each column value is separated by a comma. It's supported by Excel, Google Sheets, and most databases. Python's built-in csv module makes reading/writing CSVs easy.

csv module
Python's built-in module for reading and writing CSV files.

Object to write rows to a CSV file using writerow() or writerows().
csv.reader
Iterator that reads rows from a CSV file as lists.

Writes rows as dictionaries — uses field names as headers.
csv.DictReader
Reads rows as dictionaries — header row becomes keys.

Required when opening CSV files on Windows to prevent extra blank lines.

Character that separates values. Default is comma. Can change to ';' or '\t'.
fieldnames
List of column header names for DictWriter.
Example 1 — csv.writer and csv.reader
Python
import csv

# Write CSV
marks = [
    ["Name", "Maths", "Science", "English"],
    ["Arun", 90, 85, 78],
    ["Priya", 95, 92, 88],
    ["Karthik", 72, 68, 80],
]

with open("marks.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerows(marks)

# Read CSV using DictReader (header row = keys)

    for row in reader:

        print(f"{row['Name']:10} Total: {total}/300")
